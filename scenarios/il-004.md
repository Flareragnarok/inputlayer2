# il-004 · A key opens another app; the keyboard stays usable

## Context
Owner, 2026-11-05: Input Layer may call other apps (Termux, the Remote
Client…); the Remote Client must not live inside Input Layer; "inputlayer
must remain open when an app is called". So: a generic app key
`app:<package>[?name=value&…]`, nothing app-specific in the keyboard.
Android shows a keyboard only where the focused app has a text field or
asks for one; Termux and the Remote Client ask for it.

## Steps
1. quickequip (edit mode) → a key → a direction → "quickopen : app…" →
   search "term" → Termux, no extras (the app list has a search, owner
   2026-11-06; the layout editor's Names… has the same).
2. In any app, use that key.
3. Same with the Remote Client and extras `tab=roadmap`, with the client
   already open on Commands under other apps.
4. Use an app key for an app that was uninstalled.

## Expected
- In every app an app key opens, Input Layer is up as soon as the app is
  in front (owner, 2026-11-06: "inputlayer doesn't remain open when opening
  an app"; build 76 relied on the app asking for the keyboard).
- 2: Termux comes to the front (the running session, not a new one) and
  Input Layer is up in it.
- 3: the Remote Client's window comes to the front on Roadmap, as it was,
  and Input Layer is up (its keys reach the page).
- 4: a short message "<package> is not installed".
- The key's label is ↗ + the package's last part.

## Shows in
The owner's check on the phone; `AppKeyTest` (names, extras, round trip).

## Status
open (build 76: keyboard not up in the opened app; fix in build 77)
